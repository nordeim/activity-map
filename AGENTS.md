# AGENTS.md — ROAM (Augsburg City Guide)

Single Next.js 16 App Router app that clones `activity-map.base44.app`: an auth-gated city guide with a trip-planner home page, Eat / Stay / Do browse views with measured filter chips, place detail with booking, a Leaflet map view, favourites, and a profile with trips + bookings. Prisma/SQLite persistence, cookie-session auth. Clone remote: `https://github.com/nordeim/activity-map.git`; pushes go to the SSH remote via `docs/ssh_git_wrapper_v3.py`.

| Dev server (port 3000) | `bun run dev` |

| Prisma client after schema change | `bunx prisma generate` |
| Recreate DB from schema | `bun run db:push` |

| End-to-end smoke suite (27 checks; needs a build) | `./scripts/smoke-test.sh` |

**Gate order before every push:** `bun run lint` → `bun run typecheck` → `bun run test` (42) → `bun run build` → `./scripts/smoke-test.sh` (27, all must pass) → `bun run test:e2e` (54 Playwright checks — boots the standalone server on :3100 against its own `db/e2e.db`). There is no hosted CI; the local gate is the only gate.

First-run setup: `bun install && cp .env.example .env && bun run db:push && bun run db:seed && bun run dev`. Demo login: `sepnetflix2023@outlook.com` / `$Abcd1234` (the reference app's account, seeded locally).

## Architecture facts you would otherwise guess wrong

- **Everything except `/login`, `/privacy`, `/accessibility`, and `/api` lives in the `src/app/(app)/` route group**, whose `layout.tsx` resolves the session server-side and `redirect("/login")`s unauthenticated visitors. `/login` is a real route (server component) that bounces authenticated visits back to `/`; the two legal pages are public static routes. Do not add unguarded pages outside the group.
- **The API envelope is `{ ok: true, data } | { ok: false, error: "<message>" }`** with real HTTP status codes (401/400/404/429/201). Follow the existing route handlers' shape; do not introduce a nested error object.
- **Auth is hand-rolled** (`src/lib/auth.ts`): scrypt password hashes + HMAC-SHA256-signed stateless cookie `roam_session` (7-day TTL, httpOnly/lax, secure in production, keyed by `AUTH_SECRET`). `getSessionUser()` guards every route handler and the app layout. No NextAuth, no JWTs, no middleware. Login is rate-limited (`src/lib/rate-limit.ts`): 10 attempts/IP/15 min fixed window → `429` with `Retry-After`; in-memory, single-node only. The login PAGE (session-10) is the live's shadcn chrome: a plain white page, the rounded-16 white/95 card with the circular logo disc (`public/images/login-logo.png`), the SYSTEM-font `font-system` heading (not Inter — matches the live's wrap), Mail/Lock in-field input icons, the slate-900 `#0F172A` Sign-in button, and the bottom Forgot/Sign-up row — hosted-only flows answer with inline notices.
- **Auth navigation uses `router.refresh()`, not `window.location`** — login success and logout re-resolve the session server-side so the shell swaps without a full reload.
- **SQLite path normalization (`src/lib/db-path.ts`) is load-bearing.** A RELATIVE `file:` DATABASE_URL resolves against the first anchor directory carrying `prisma/schema.prisma` — like the Prisma CLI — so `file:../db/custom.db` means `<repo>/db/custom.db` regardless of CWD. Three traps are already solved; don't reintroduce them: (1) `next build` copies `prisma/schema.prisma` into `.next/standalone`, so a plain CWD rule would resolve against BUILD OUTPUT — `candidateRoots()` skips standalone subtrees and upgrades an in-repo standalone anchor to the repo root; (2) the **Turbopack production minifier mis-compiles multi-return helpers** (it dropped a `return repo` in a multi-return variant, silently) — `standaloneRepoRoot()` and friends are single-exit ON PURPOSE, keep them that way; (3) some `.env` loaders pass quotes through — `resolveDatabaseUrl` strips them. Contract pinned by `tests/db-path.test.ts` (17 checks). Always `import { db } from "@/lib/db"`; never construct `PrismaClient` directly.
- **The dev/start/db scripts pin `DATABASE_URL` explicitly** (`dev`, `start`, `db:push`, `db:seed` — all set `DATABASE_URL=file:../db/custom.db` inline). Stray parent-directory `.env` files or exported shell vars with an absolute path once hijacked both the runtime and the seed — keep the pinning.
- **Standalone server must start from the project root** (`output: "standalone"` in `next.config.ts`). npm/bun scripts guarantee the working directory; running `server.js` from elsewhere breaks SQLite resolution.
- **Schema changes use `db push`, not migrations** (`prisma/migrations/` does not exist). `bun run db:seed` is idempotent — it wipes and reseeds domain tables from `prisma/data/{eat,stay,do,home,map}.json`: the 12+12+18 places captured from the live app PLUS 27 **home-only showcase rows** (`status: "home"` — 5 route stops, 6 sights, 16 restaurants) PLUS 9 **map-demo rows** (`status: "map"`, `map-*` slugs, real lat/lng — the hardcoded array the live map page renders). The demo user seeds as `name: "sepnetflix2023"` (session-14: the live account's identity — the profile h1) with the avatar initial derived from the EMAIL (`Navbar userEmail`) and the EMAIL rendered as the profile subtitle line (the live shows "sepnetflix2023@outlook.com" there — "Your Roam account" is gone).
- **Home-only and map-demo places are invisible to browses and counts by design.** `listPlacesForUser`/`countPlaces` filter `status: "published"` (so Eat/Stay/Do stay 12/12/18 and the category cards stay correct), while `getPlaceBySlug` does NOT filter status — `/place/home-route-*`, `/place/home-restaurant-*`, and `/place/map-*` resolve like any place. `listHomePlaces(prefix, userId)` and `listMapPlaces(userId)` in `src/lib/places.ts` select them by status. The map page is fed by the 9 `status: "map"` demo places only (live parity — the live app's map is a hardcoded array, not entity-fed). The home page composition (hero + glass planner → glass category cards → sticky Recommended Route → blue Highlighted Restaurants → Choose Your Vibe stay showcase → Highlighted Sights → footer) mirrors the live app re-measured sessions 10+12: the hero photo is 591px on phones / 900px at md / 938px at lg and slides UNDER the transparent sticky header at md (`-mt-[73px]`), with the h1 at the live's measured positions (pt 203/290) and a 126px mobile planner gap; the three glass category cards (263px, radius 20, 28×28 glass icon cells, 12px/500 two-line rows, the live icon set incl. Category pages' heading blocks and the home showcase sections (CategoryCards, StayShowcase, HighlightedSights, SiteFooter) are server components that query Prisma directly.
- **Leaflet must never render on the server** — `MapExplorer` mounts `LeafletCanvas` through `next/dynamic` with `ssr: false`. Importing `react-leaflet` in a server component crashes the build.
- **Tailwind v4 is CSS-first: there is NO `tailwind.config.*`.** Design tokens live in `src/app/globals.css` under `@theme` (re-measured session 3: `--color-cream #F8F7F4`, `--color-cream-deep`/`--color-surface2 #F2F1EE`, `--color-ink #0E0E0E`, `--color-roam #571AFF`, `--color-electric #4D61FF` blue band, plus `--color-secondary/-muted/-line/-border`; `--font-sans` (Inter) / `--font-serif` (Libre Baskerville) / `--font-nav` (Inter — the live app dropped Poppins in its session-3 redesign), shadows, `--radius-4xl`) plus `@utility` primitives (`bg-grid`, `no-scrollbar`, `hero-shade`). Extend the theme there, not in a config file. The known v4 mobile-nav failure classes (no-nav / invisible / clipped / under-layer / breakpoint mismatch) are regression-pinned by `tests/e2e/mobile-navigation.spec.ts`; the Navbar keeps the `no-scrollbar` horizontal overflow as a safety valve — don't remove it. The nav wordmark is the live app's image logo (`public/images/roam-logo.png`) rendered with the reference's two-span crop technique — the mobile wordmark span must stay ≤62px wide or the 390px bar overflows (failure class D). Computed-style assertion gotchas: `rounded-full` serializes as `calc(infinity*1px)` (≈3.35e7px) and α-blended backgrounds arrive as `oklab()` — assert numeric radii / shadows instead of exact strings.
- **The navbar is a two-mode chrome re-measured session 6.** Below `md`: a FIXED top cream-glass tab-bar (bg `#F8F7F4/60` + blur, border-b `rgba(14,14,14,0.08)`, 52px, capped ≤430px, centered) — text-only 12px Inter links (active 700/`#0E0E0E`, inactive 500/40%), right cluster = MapPin/Heart/User 18px icons, and on home the hero photo slides UNDER the glass. From `md` up: a sticky transparent header (pt-[9px] px-6 pb-2, flex justify-center) wrapping the centered WHITE floating PILL (`h-14`, max-w 820, radius 999, 1px `#E8E6DC` border all round, shadow `0 2px 12px rgba(14,14,14,0.08)`) with 13px Inter icon+text links — active 700 ink on the `rgba(14,14,14,0.08)` pill, inactive 500 `#555550` — heart + black avatar disc right cluster, and a hide-on-scroll-down choreography. Don't "fix" the asymmetry. The white icon-cell footer pill renders from the `(app)` LAYOUT on every authenticated page — don't re-add per-page footers.
- **Filter chips are data-measured, not invented** (`src/lib/filters.ts`): eat gets four special chips (Open now / Near me / Under €100 / Trending) plus tag chips; stay/do chips literally mirror the reference entities' tags. Chips AND-compose; the text query matches name/neighborhood/sub-category/description/tags. Pure seam — extend `tests/filters.test.ts` when you extend it.
- **Remote images are limited to `media.base44.com` and `z-cdn.chatglm.cn`** (`next.config.ts` `remotePatterns`) — the reference app's media CDN. Add hosts there, never `unoptimized`.
- **TypeScript is strict except `noImplicitAny: false`** (kept intentionally). `tsconfig.json` and ESLint both exclude `skills/`.

## Conventions that differ from defaults

- Prices format via `src/lib/utils.ts` (`formatPrice` en-IE EUR, `priceRangeSymbols` 1–4 → €..€€€€ + `priceRangeParts` for the ACTIVE+DIMMED card display, `formatDuration` minutes → "2 h"); planner URL/date-label helpers live in `src/lib/planner.ts`. Don't hand-roll display formatting in components.
- Place rows store JSON arrays in plain string columns (`vibeTags`, `galleryImages`, …) — SQLite has no array type; `toPlaceDTO` in `src/lib/places.ts` is the only sanctioned parser, and every API payload uses the `PlaceDTO` shape from `src/types/index.ts` (including the per-user `saved` flag).
- Bookings persist the session-3 request-form fields (`name`, `surname`, `time`, `phone`, `email`, `message` on the `Booking` model); guests clamp to the place's `minParty`/`maxParty` server-side; the profile view groups bookings with place names client-side.
- E2E auth is shared: the Playwright `setup` project signs in ONCE into `tests/e2e/.auth/user.json` (storageState) because per-test logins would trip the rate limiter. `auth.spec.ts` opts out with an empty storageState to test the logged-out surface. Spec navigations use `waitUntil: "domcontentloaded"` — the home page pulls ~35 card images from the reference CDN and the full `load` event has hit spurious 45s timeouts under network contention. Never leave a stray server on :3100 — `reuseExistingServer` reuses a STALE build mid-iteration (session 6: a stale probe server produced a phantom favourites failure); also close stray headless-browser sessions + the dev server before a suite run — a full E2E pass with several browser daemons alive exhausted the 4GB sandbox and crashed the browser targets (session-14 lesson). The auth spec's /login gotos use `domcontentloaded` too (session-14: the CDN-font `load` flake).
